## 并发读写 Slice 的问题

> Go 语言是如何处理 slice（切片）在多线程下的并发安全问题的吗？ （提示：虽然 String 是不可变的，是并发安全的；但 Slice 是可变的，它在并发追加（Append）时会发生什么惊人的事情？）

首先，Slice 本质上就是一个存着指针的‘小头部’。并发操作它，其实就是多个人在抢同一个底层数组，这肯定会出事：

第一是 **数据覆盖**。你也 append，我也 append，大家都以为写的是同一个位置，结果数据互相踩踏，直接丢了。
第二是 **扩容‘脑裂’**。大家都发现容量不够，各自去申请新数组‘搬家’。结果你搬你的，我搬我的，最后全局变量指向谁的新家？完全随机。输的那一方写的数据全丢了，而且还制造了一堆没用的新数组，GC 压力直接爆炸。

所以，想安全，要么老老实实加锁，要么用 Channel 汇聚。
